# 別の作品でキャラ当てゲームを作る手順

このリポジトリは「ポケゲッサー」型のキャラ推理ゲームの**共通エンジン**＋**イナズマイレブン用の設定・データ**です。
別の作品（例：ワンピース、鬼滅の刃、ポケモン…）で作るときは、**エンジンはそのまま**で次の2つだけ差し替えます。

| 差し替えるもの | ファイル | 内容 |
|---|---|---|
| 題材の設定 | `config.js` | タイトル、ヒント項目、フィルター、クレジット |
| キャラデータ | `data.src.js` → `node build-data.js` → `data.bin` | キャラ一覧（暗号化して配布） |

共通エンジン（触らない）：`index.html` / `style.css` / `app.js` / `loader.js` / `build-data.js`

---

## 1. 全体の仕組み

```
ブラウザ
 ├ index.html      画面の骨組み（文言は config.js から流し込む）
 ├ config.js       題材ごとの設定（★差し替え）
 ├ app.js          ゲーム本体（ソロ / 対戦、判定、描画）… 題材非依存
 ├ loader.js       URLの #k=カギ で data.bin を復号 → GAME_START(data)
 └ data.bin        暗号化されたキャラデータ（★差し替え）

対戦モード: PeerJS(WebRTC) の P2P。ホストが正解と進行を持ち、ゲストは推理を送るだけ。
           サーバー不要。ルームIDは config.id + 6桁コード。
公開:      GitHub Pages（静的ファイルを置くだけ）。カギ付きリンクを知っている人だけ遊べる。
```

### 判定ルール（`config.attrs` の `type`）
| type | 使い方 | 判定 |
|---|---|---|
| `exact` | 性別・属性など単一値 | 🟩一致 / ⬜不一致 |
| `set` | 所属チームなど複数値（配列） | 🟩全一致 / 🟨1つ以上共通 / ⬜共通なし |
| `ordinal` | 学年・初登場作品・身長など順序のある値 | 🟩一致 / ▲正解はもっと上 / ▼正解はもっと下 |

`ordinal` は `orderKey`（数値のキー）で大小を判断します。表示用の文字列と数値を分けたいとき（学年「中2」と順序 3）に使います。`labels: "リスト名"` を付けると、数値インデックスを `data.lists.リスト名[値]` で表示名に変換します。

## 2. データ形式（`data.src.js`）

```js
window.INA_DATA = {           // 変数名は何でもよい（build-data.js は { … } の部分だけ読む）
  lists: {                    // ordinal の表示名や、フィルターの選択肢
    works: ["作品1", "作品2", …],       // フルネーム
    short: ["1", "2", …],               // タイル用の短い名前
  },
  chars: [
    { n: "円堂守", k: "えんどうまもる", a: "円堂", i: "画像ID", m: 1,
      t: ["雷門中", "イナズマジャパン"], p: "GK", g: "男", e: "山",
      gr: "中2", go: 3, f: 0 },
    …
  ]
};
```

- キー名は自由。`config.fields` と `config.attrs[].key` で対応づけます
- `m: 1` を付けたキャラが「メインキャラのみ」の出題対象（`config.difficulty` を使う場合）
- 画像は任意。`config.imageBase + i + imageExt` で読み込みます（`imageBase` を空にすれば画像なし）
- **推奨規模**：出題候補（メイン）は 50〜200、検索候補は数百〜数千でも動きます

### データの集め方（例）
1. 公式サイト・Wiki・攻略サイトの一覧ページを確認し、必要な属性が載っているページを探す
2. ページを取得してパースするスクリプトを書く（このリポジトリの元データは公式図鑑を Node で取得・整形した）
3. 同名キャラの統合、表記ゆれ、順序値（`go` など）の付与
4. 「メインキャラ」の一覧を手作業で作り `m:1` を付ける
5. `data.src.js` に書き出し、`node build-data.js` で `data.bin` を生成

## 3. `config.js` の書き方（鬼滅の刃の例）

```js
window.GAME_CONFIG = {
  id: "kimetsu-guesser",                 // ★必ず題材ごとに変える（保存領域・ルームIDの接頭辞）
  siteUrl: "https://<user>.github.io/kimetsu-guesser/",
  title: "キメツゲッサー",
  kicker: "KIMETSU NO YAIBA CHARACTER GUESSER",
  heroTitle: "鬼滅の刃のキャラを\nヒントから当てよう",
  itemLabel: "キャラ", unit: "人",
  credit: "非公式ファンゲームです。", creditLink: null, creditTail: "©吾峠呼世晴／集英社",
  soloMax: 10, maxPlayers: 4,
  imageBase: "", imageExt: "",           // 画像なし
  fields: { name: "n", kana: "k", alias: "a", image: null, main: "m" },
  suggestSub: (c) => c.side,
  attrs: [
    { key: "side",   label: "所属",   type: "exact" },                    // 鬼殺隊 / 鬼 / その他
    { key: "breath", label: "呼吸・血鬼術", type: "set", wide: true, empty: "なし" },
    { key: "rank",   label: "階級",   type: "ordinal", orderKey: "rankNo", up: "正解はもっと上の階級", down: "正解はもっと下の階級" },
    { key: "g",      label: "性別",   type: "exact" },
    { key: "vol",    label: "初登場巻", type: "ordinal", up: "正解はもっと後の巻", down: "正解はもっと前の巻" },
  ],
  filter: null,                          // 出題範囲フィルターを使わない場合
  difficulty: { mainLabel: "主要キャラのみ", mainNote: "約60人", allLabel: "全キャラ", allNote: "名前のある全キャラ" },
  notes: ["階級は最終時点のもの。"],
  qaExample: "鬼ですか？",             // 質問モードの質問例（入力欄に「例：…」と出る）
};
```

## 4. 作業手順（新しいリポジトリを作る場合）

```bash
# 1) このリポジトリを複製
git clone https://github.com/so-sons/inaguesser.git kimetsu-guesser
cd kimetsu-guesser
rm -rf .git .secret-key data.bin data.src.js
git init -b main

# 2) config.js と data.src.js を作る（上記参照）

# 3) 暗号化データを生成（.secret-key が自動生成され、共有リンクが表示される）
node build-data.js

# 4) 動作確認（任意の静的サーバー）
npx -y http-server . -p 5173 -c-1
#   → http://localhost:5173/#k=<表示されたカギ>

# 5) 公開
git add -A && git commit -m "初回"
gh repo create <user>/kimetsu-guesser --public --source=. --push
gh api -X POST repos/<user>/kimetsu-guesser/pages -f "source[branch]=main" -f "source[path]=/"
#   → https://<user>.github.io/kimetsu-guesser/#k=<カギ>
```

`.gitignore` により `data.src.js`（平文データ）と `.secret-key` はコミットされません。**`.secret-key` を消すとカギが変わり、配布済みリンクが無効になる**ので注意（意図的にリンクを無効化したいときに使う）。

## 5. チェックリスト
- [ ] `config.id` を題材ごとに変えた（同じだと別ゲーム同士でルームが混ざる）
- [ ] `config.siteUrl` を公開URLに合わせた
- [ ] `attrs` の `key` が `data.src.js` のキーと一致している
- [ ] `ordinal` の項目に `orderKey`（または数値そのもの）がある
- [ ] `filter.options` / `attrs[].labels` が `data.lists` の名前と一致している
- [ ] `m:1` のキャラが 50 人以上いる（少なすぎるとすぐ同じ問題が出る）
- [ ] 画像を使う場合は権利面を確認（このリポジトリでは公式サイトの画像を直リンクしており、グレー）
- [ ] フッターのクレジット表記（非公式であること、©表記）

## 6. 新しいチャットで頼むときのテンプレート

```
https://github.com/so-sons/inaguesser のエンジンを使って、
「＜作品名＞」版のキャラ当てゲームを作ってほしい。
手順は docs/新しい題材で作る.md に書いてある。

- ヒント項目: ＜例: 所属 / 呼吸 / 階級 / 性別 / 初登場巻＞
- メインキャラの目安: ＜例: 60人＞
- データの出典: ＜例: 公式サイトのキャラ一覧 URL、または「Wikiから」＞
- 画像: ＜使う / 使わない＞
- 公開先: GitHub Pages（リポジトリ名 ＜例: kimetsu-guesser＞、カギ付きリンク）
```
